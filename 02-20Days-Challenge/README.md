# 阶段二：工坊开放式项目挑战（8 选 1 · 60 分）

## 选定项目：项目三 · 基于手机内置传感器的日常旋转机械/电器异常声振诊断仪

> 官方原文：利用手机麦克风与加速度计采集电风扇、吹风机等设备在正常与模拟异常工况（不同档位、扇叶轻微失衡、遮挡等）下的声振信号，借助 AI 编写频谱（FFT）特征分类脚本。
> 材料要求：智能手机 + 电风扇/吹风机/单车。**无需采购、无需焊接、无需借用设备。**

**选型理由**：8 个项目中唯一"零材料成本 + 无硬性连续天数门槛"的项目。其余项目中，项目四要求连续 7 天日志（11/19 起已不可能），项目六要求 5 天×12 小时（需先有传感器与主控），项目一要求 24 小时实测（需借 ESP32-CAM 与电流表），项目二需训练视觉模型。本项目全部数据一晚可采完，后续工作集中在算法与报告。

## 五种工况定义

| 编号 | 工况 | 具体做法 | 考察点 |
|---|---|---|---|
| C1 | 正常·低档 | 电风扇 1 档，无任何干扰 | 基线 |
| C2 | 正常·高档 | 电风扇 3 档（或最大档） | 转速差异 → 基频与谐波整体上移 |
| C3 | 扇叶失衡 | 在其中一片扇叶贴一小块胶带（约 2 g），保持 3 档 | 失衡 → 出现转频边带与低频调制 |
| C4 | 进风遮挡 | 用书本挡住进风口约 1/2，保持 3 档 | 风阻增大 → 宽频噪声抬升、转速下降 |
| C5 | 停机静默 | 关机，仅录环境本底噪声 | 对照基线，用于判断"是否在运行" |

> C3 的胶带请**保留到全部采集结束**，中途改变配重会导致数据不可比；每采完一组要在日志里记一笔。

## 采集方式（两种路线，已选手机长录音）

### 路线 A（采用）：手机长录音 + 脚本自动切段

手机麦克风频响比笔记本宽，能保留风扇 20–40 Hz 的转基频与失衡边带，笔记本麦克风在 100 Hz 以下已衰减，这恰恰是 C3「扇叶失衡」的关键特征。

1. 手机录音机，**格式优先选 WAV**（若无则该 m4a 亦可，脚本用 ffmpeg 转码）。
2. 手机竖立固定在桌面上，麦克风孔正对出风口 **20–30 cm**，开飞行模式。
3. 每个工况录 **一条 3 分钟**长音频，开头留 5 秒静默，中途不碰手机、不说话。
4. 文件重命名为 `C1` ~ `C5`，放同一目录。
5. 执行：
   ```bash
   python tools/import_phone_audio.py --src "手机录音目录"
   ```
   自动转 44.1k/16bit/mono → 跳过开头 5 秒 → 每工况切 15 段 × 10 秒 → 写入 `data/wav/` 与 `data/录音索引.csv`。

### 路线 B（备用）：笔记本逐段录制

手机不便时可用 `tools/record_vibration.py`，自动倒计时并逐段录制，参数同上。

## 采集规范（决定数据可用性）

1. **采集位置全程固定**：距设备正前方 20–30 cm，同一高度、同一角度。位置一换，频谱整体就变了。
2. 统一 **44.1 kHz / 16 bit / 单声道 WAV**（脚本负责转码与切段）。
3. 开机后**等 3 秒转速稳定**再进入有效区间；手机长录时开头留 5 秒静默供脚本跳过。
4. 同一工况的 15 组**连续采完**再换工况，不要来回切换档位。
5. 环境保持安静（关门窗、关空调），但**不要刻意消音**——真实环境噪声是抗噪报告的素材。
6. 盲测集（`wav-blind/`）**必须另找时间重新采**，每工况 5 段，共 25 段。用训练集里的数据去测自己是自欺欺人，面试一问就露。

## 目录

- `data/wav/`：训练集原始录音（75 段）
- `data/wav-blind/`：盲测集（25 段）
- `data/录音索引.csv`：每段的工况、档位、距离、时间等元信息
- `src/`：源码（特征、训练、推理）
- `tools/`：采集与数据处理脚本（`record_vibration.py` 逐段录制、`import_phone_audio.py` 长录音转码切段）
- `process_logs/`：每日过程日志（官方强制要求跨多日连续数据）
- `iterations/`：每轮迭代的变更说明与指标对比

## 每日必做

**每天提交一次 process_log，哪怕当天只写了 10 行。** 官方对第二阶段的要求里写着"强制要求提交跨多日连续过程数据"，断档的日志比写得粗糙的日志更致命。
